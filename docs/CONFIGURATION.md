# 配置参考

核对日期：2026-10-21。以 `app/config.py`、`app/main.py`、`config.example.json` 为准；配置示例不代表学校实际开放时间或当前用户设置。

## 两种配置不要混用

| 类别 | 保存位置 | 修改方法 | 生效时机 |
| --- | --- | --- | --- |
| 部署级参数 | 项目根目录 `config.json` | 部署者编辑文件 | 重启服务 |
| 账号预约参数 | `logs/accounts.sqlite3` | 网页、`PUT /api/config`，或管理员设置接口 | 保存为当前账号配置；已启动预约任务保留参数快照，保活循环读取最新账号设置 |

`config.example.json` 只用于首次安装。不要用它覆盖已有生产配置。旧版混合配置只在首次注册第一个账号时提取个人字段，不是每次启动都覆盖账号数据库。

## 部署级参数

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `base_url` | `https://libzw.ustb.edu.cn` | 图书馆服务地址 |
| `request_timeout_seconds` | 15 | 单次图书馆 HTTP 请求超时秒数，不等于整个工作流超时 |
| `auth_session_ttl_seconds` | 300 | 未完成扫码会话的回收时间，不是已登录会话的强制寿命 |
| `max_browser_sessions` | 5 | 全部账号合计容量，允许 1–16 |
| `max_sessions_per_account` | 2 | 单账号容量，允许 1–4；已登录会话另有单账号最多 1 个的规则 |
| `session_cleanup_interval_seconds` | 30 | 回收检查间隔，允许 10–300 秒 |
| `memory_log_interval_seconds` | 60 | 资源日志采样间隔，允许 30–3600 秒 |
| `library_navigation_interval_seconds` | 60 | 未完成/失败的完整认证跳转冷却，允许 10–600 秒，不等于轻量探测间隔 |
| `headless` | true | 无 UI 浏览器；服务器部署保留 true |

这些参数在构造账号运行配置时覆盖旧的个人同名字段，不能通过普通账号配置接口更改。不要把 `submit_enabled` 加进现代部署配置后就认为已为所有账号开启提交。

## 账号预约参数

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `login_source` | `jwgl` | `jwgl` 或 `library`，影响下一次创建扫码会话 |
| `room_id` | 102057443 | 区域 ID，应通过实时区域接口获取 |
| `room_name` | 图西楼四楼北区 | 显示名称，应与区域 ID 对齐 |
| `seat_names` | `["F4B114"]` | 候选座位名，提交时实时解析设备 ID |
| `target_date` | `tomorrow` | 单次任务目标；网页会保存具体 `YYYY-MM-DD` |
| `start_time` / `end_time` | `07:00` / `07:40` | 必须符合座位实际开放时间和预约规则，默认值不保证可用 |
| `poll_interval_seconds` | 30 | 网页只读座位刷新，接口允许 5–86400 秒，不是自动预约重试 |
| `keepalive_enabled` | true | 是否运行账号的学校/图书馆保活 |
| `keepalive_interval_seconds` | 300 | 常规保活间隔，接口允许 30–86400 秒 |
| `auto_trigger_time` | `08:00:00` | 北京时间触发点，不代表学校开放时间 |
| `auto_retry_interval_seconds` | 30 | 自动预约失败重试间隔，接口允许 5–86400 秒 |
| `daily_auto_enabled` | false | 每日模式，普通账号通过每日 start/stop 接口切换，不是 `PUT /api/config` 可写字段 |
| `submit_enabled` | false | 允许真正预约提交；开启后仍需明确手动确认或显式启动自动任务 |

管理员可通过自己的管理接口修改用户设置，包括每日开关；这不授予管理员借用该用户学校凭证提交预约的权限。普通设置接口的模型与管理员接口的校验不完全相同，建议按以上格式填写，并在启动任务前查询实际座位时间范围。

## 日期、时区与任务

- 网页目标日期提供今天、明天、后天，保存为具体日期，避免午夜后漂移。
- 单次任务固定目标日期，等待下一次北京时间触发点；目标必须是触发日的今天或明天。
- 每日模式忽略单次固定目标日期，每次预约触发日期的次日。
- 指定座位即时提交接口只允许今天/明天；区域空闲及单座位时段查询可到后天。
- 监控和本人预约明细只查询今天/明天；监控额外支持 `both`。
- 控制接口日期别名是 `dayafter`；不要直接把网页内部的 `day_after_tomorrow` 值传给它。
- 修改已保存参数不会改写正在运行任务的快照。想更新已排定任务，应停止后重新启动。
- 保活开关/间隔会被保活循环动态读取，不应把预约任务的快照规则理解成所有设置都必须重启。保活任务已退出时，重新建立或恢复认证后应检查 `keepalive_running`，不能只看保存的开关。
- 账号、参数、历史持久化；浏览器会话和应用 Cookie 令牌不持久化。重启后重新扫码并核对任务状态。

## 代码内固定行为

以下不是 `config.json` 可调整参数：

- Basic 与 POST 监控共用账号密码认证限流：每来源 IP 每分钟 30 次。
- 监控缓存 30 秒，每次远端查询限时 20 秒，等待锁与清理另有短超时；`both` 串行查询两天，客户端建议设置 50 秒超时。
- 总览验证限时 20 秒，客户端清理最多另等 2 秒；不返回明细也验证凭证。
- 浏览器健康采样每 60 秒，单次探测超时 3 秒；Docker 每 30 秒读取一次健康接口。
- 文件日志单份 5 MiB、5 个备份；Docker 日志轮转见 Compose，当前为 10m × 3。

## 打包与备份

发布源码不应包含 `config.json`、`.venv`、`logs`、SQLite 数据库、Cookie、Token、HAR 或浏览器认证目录。运行迁移则必须保留配置和 `logs`；源码发布与服务迁移是两种不同操作。不要把保留账号数据等同于能够恢复学校登录。
